02

설치와 모델 받기

라마

다운로드는 시작만 걸어둬. 기다리지 말고 다음으로!

Ollama를 깔고, 모델 다운로드를 걸어둡니다. 받는 동안 이론을 배울 거예요.

오늘의 전략 다운로드는 시작만 해두고 기다리지 않습니다. STEP 2에서 명령어를 실행해 진행률이 돌기 시작하면, 창을 닫지 말고 그대로 둔 채 다음 이론 챕터로 넘어가세요. 이론이 끝날 때쯤 완료돼 있습니다.
STEP 1

Ollama 설치

배포된 OllamaSetup.exe를 실행하고 기본값으로 진행하세요.

파일이 없거나 집에서 설치한다면 → ollama.com/download/windows (바로 받기: OllamaSetup.exe)

관리자 권한 필요 없습니다 내 계정 안에 설치되므로 실습실 PC의 권한 제한과 무관합니다.

설치가 끝나면 작업표시줄 오른쪽에 Ollama 아이콘이 생깁니다.

STEP 2

모델 가져오기 — 가장 중요한 단계

두 가지 방법이 있습니다. 조교 안내에 따라 하나만 하세요.

■ 방법 A · 배포 파일 복사 (권장 — 훨씬 빠릅니다)

  1. 작업표시줄 Ollama 아이콘 우클릭 → Quit (복사하는 동안 꺼져 있어야 합니다)
  2. 배포된 blobs, manifests 두 폴더를 아래 경로에 통째로 붙여넣기
    %USERPROFILE%\.ollama\models
    탐색기 주소창에 붙여넣으면 해당 폴더로 이동합니다. 없으면 만드세요. OLLAMA_MODELS를 따로 설정한 PC는 조교가 안내한 경로를 사용합니다.
  3. 시작 메뉴에서 Ollama 다시 실행
🔴 가장 많이 하는 실수 manifests 폴더를 빠뜨리는 것. blobs만 복사하면 파일은 다 있는데 모델 목록에 아무것도 안 뜹니다. 원인을 찾기 어려우니 두 폴더 다 복사했는지 지금 확인하세요.

■ 방법 B · 직접 다운로드

인터넷에서 바로 받습니다. Ollama가 켜져 있어야 합니다.

Win+R → cmd → 엔터. 검은 창에 입력:

ollama pull qwen2.5-coder:3b ollama pull qwen2.5-coder:1.5b-base

두 번째는 VS Code 자동완성용입니다 (09 VS Code 연결에서 설명).

진행률이 표시되고, 합쳐서 2.9GB라 회선 상태에 따라 5~20분 걸립니다. success가 뜨면 완료입니다.

여기서 멈추고 이론으로 넘어가세요 진행률 숫자가 올라가기 시작했으면 성공입니다. 창을 닫지 말고 그대로 두세요. 끝날 때까지 쳐다볼 필요 없습니다.
18명이 동시에 받으면 느려집니다 교육장 회선을 다 같이 나눠 쓰게 됩니다. 조교가 방법 A를 안내했다면 그쪽을 쓰세요. 직접 받아야 한다면, 다 받을 때까지 기다리지 말고 먼저 끝난 사람부터 다음 단계로 넘어가면 됩니다.
VRAM이 부족하다면먼저 자동완성을 끄고 채팅용 3B만 사용합니다. 그래도 실행이 어려우면 조교에게 알리고 짝 실습으로 합류하세요. 채팅 모델을 임의로 1.5B-base로 바꾸지 않습니다.
STEP 3

환경변수 2개 확인 — 교사 사전 설정 / 선택

대화 기억 공간(KV 캐시)을 절반으로 압축해서, 같은 그래픽카드로 더 긴 대화를 가능하게 하는 설정입니다. (자세한 설명은 06 내 PC에 맞추기)

Win 키 → "환경 변수" 검색 → 계정의 환경 변수 편집 → 새로 만들기로 두 개 추가:

OLLAMA_FLASH_ATTENTION = 1 OLLAMA_KV_CACHE_TYPE = q8_0

추가한 뒤 트레이 Ollama 아이콘 → Quit으로 완전히 종료하고, 시작 메뉴에서 다시 실행하세요. 진행 중인 다운로드가 끝난 뒤 적용합니다. 이 설정은 전체 VRAM이 아니라 KV 캐시 사용량을 줄입니다.

STEP 4

확인

Win+R → cmd → 엔터. 검은 창에 입력:

ollama list

qwen2.5-coder:3b가 뜨면 성공입니다. 아무것도 안 뜨면 STEP 2의 manifests를 확인하세요.

그래픽카드와 드라이버 정보도 확인해 둡시다:

nvidia-smi

카드 이름과 메모리(6GB 내외), 드라이버 버전이 나옵니다.

준비 완료 확인
  1. ollama run qwen2.5-coder:3b로 실행합니다.
  2. “HTML 버튼을 만드는 코드 한 줄을 보여줘”에 답을 받습니다.
  3. 새 cmd 창에서 ollama ps를 실행해 MODEL과 PROCESSOR를 봅니다. GPU/CPU 배치를 조교와 확인합니다.

nvidia-smi에 GPU가 보이는 것과 모델이 GPU를 쓰는 것은 별개입니다.

⚠️ 드라이버 551.61 이상이어야 합니다 미만이면 그래픽카드를 못 쓰고 CPU로 동작해 매우 느려집니다.

확인하는 방법 (셋 중 아무거나)

  • nvidia-smi — 오른쪽 위 Driver Version
  • 바탕화면 우클릭 → NVIDIA 제어판 → 좌측 하단 시스템 정보
  • Win+R → dxdiag → 디스플레이 탭

낮으면 업데이트

nvidia.com/ko-kr/drivers 에서 카드 모델을 선택해 받거나, NVIDIA 앱으로 자동 업데이트. 수업 중에 하기엔 오래 걸리니 조교에게 먼저 알려주세요.

03

LLM이 뭔가요

라마

나 같은 애들은 사실 '다음 단어 맞히기' 선수야.

Large Language Model — 커다란 언어 모델.

하는 일은 딱 하나입니다: 다음 단어 맞히기

"오늘 아침에 밥을 ___" 다음에 올 말을 맞히는 것. 이 단순한 작업을 인터넷 전체 분량의 글로 어마어마하게 훈련시켰더니, 번역도 하고 요약도 하고 코드도 짜는 물건이 나왔습니다.

그래서 LLM은 "알고 있는 것"이 아니라 "그럴듯한 것"을 내놓습니다. 이게 오늘 실습 내내 체감하게 될 핵심 성질입니다. 자신 있게 틀린 답을 말하는 이유이기도 하고요.

파라미터 — 모델의 "크기"

모델 이름에 붙는 4B, 7B, 70B의 B는 Billion(10억), 즉 파라미터 개수입니다. 뇌세포 개수 같은 거라고 생각하면 얼추 맞습니다.

크기비유어디서 도나
1B~4B간단한 일은 척척, 복잡한 건 헤맴노트북, 게이밍 PC ← 오늘 우리
7B~14B웬만한 건 해냄좋은 그래픽카드 (12~24GB)
30B~70B꽤 똑똑함전문가용 장비
200B+ChatGPT, Claude 급데이터센터 — 개인은 불가능
미리 알아두기 오늘 쓸 모델은 가장 작은 축입니다. ChatGPT를 기대하면 실망합니다. 대신 내 컴퓨터에서, 공짜로, 인터넷 없이 돕니다. 그 대가를 오늘 직접 확인해 봅시다.

왜 내 PC에서?

라마

인터넷이 없어도, 내가 네 컴퓨터 안에 있으면 되잖아?

ChatGPT 놔두고 왜 이 고생을 하는가.

클라우드 (ChatGPT, Claude)로컬 (오늘 우리)
성능압도적제한적
비용서비스에 따라 무료·구독·사용량 과금하드웨어·전기 비용
인터넷반드시 필요없어도 됨
내 데이터서버로 전송됨오늘의 로컬 연결에서는 PC에서 처리
사용 제한횟수·속도 제한내 하드웨어 자원에 제한
서비스 종료회사 사정에 좌우내 파일이라 영향 없음

현실에서 로컬이 답인 경우

  • 회사 소스코드 — 외부 전송을 제한하는 조직에서는 내부 처리 방식이 필요합니다
  • 민감한 기록·미공개 연구 — 조직의 데이터 처리 규정을 먼저 확인해야 합니다
  • 인터넷이 없는 환경 — 폐쇄망, 공장, 군, 비행기
  • 대량 반복 처리 — 작업량에 따라 API 비용과 로컬 장비·운영 비용을 비교합니다
오늘의 진짜 학습 목표 "로컬이 좋다"가 아니라 "어떤 일에 로컬을 쓰고 어떤 일에 클라우드를 쓸지 판단할 줄 아는 것"입니다. 양쪽을 다 써본 사람만 판단할 수 있습니다.
05

모델 고르는 법

라마

덩치보다 뭘 배웠느냐가 중요해. 나는 코딩만 팠거든.

모델을 고를 때 봐야 하는 세 가지 축.

선택 읽기 · 수업 뒤에 다시 봐도 좋아요오늘은 채팅용 3B와 자동완성용 1.5B-base의 역할만 구분하면 됩니다.
모델과 메모리 자세히 알아보기

① 용도 — 범용이냐 코딩 특화냐

종류용도
범용 (Instruct/Chat)일상 대화, 글쓰기, 요약
코더 (Coder)코드 생성·설명·수정 ← 오늘 이걸 씁니다
임베딩 (Embedding)문서 검색용. 대화는 못 함
비전 (Vision)이미지를 보고 설명

같은 4B라도 코더 모델이 코딩을 훨씬 잘합니다. 크기만 보고 고르면 안 되는 이유입니다.

② 양자화 — 모델을 압축하는 기술

④ KV 캐시 — 대화를 기억하는 공간

설치할 때 OLLAMA_KV_CACHE_TYPE = q8_0을 넣었죠. 그게 뭔지 알아봅시다.

왜 필요한가

LLM은 입력으로 전달된 대화와 코드를 문맥으로 사용합니다. 이미 계산한 부분까지 매번 다시 계산하면 비효율적이므로 이전 계산 결과를 재사용합니다.

그래서 앞 내용을 계산해둔 결과를 메모해 둡니다. 이 메모장이 KV 캐시예요. 실제 요약문을 저장하는 것은 아닙니다. 책을 읽다가 앞 장을 다시 펼치지 않으려고 요점을 적어두는 것과 같습니다. 이전 토큰의 K/V 계산을 재사용합니다. 새 토큰은 앞선 문맥을 참조하므로 긴 대화의 계산 비용이 사라지는 것은 아닙니다.

문제는 — 이 메모장도 VRAM을 먹습니다

그래픽카드 6GB ├─ 모델 가중치 ← 다운로드 크기와 실행 메모리는 다름 ├─ KV 캐시 ← 컨텍스트 길이·자료형·동시 요청에 영향 └─ 실행 작업 공간 ← 기타 프로그램의 GPU 사용도 고려

모델을 넣었다고 끝이 아닙니다. 캐시 할당 방식은 실행 환경에 따라 다르며, 긴 컨텍스트를 설정할수록 필요한 공간이 커집니다. 남은 공간을 다 쓰면 느려지거나 터집니다. 긴 컨텍스트에서는 캐시가 차지하는 비중이 커질 수 있습니다.

컨텍스트와의 관계

모델 설명에 나오는 32K, 128K 같은 숫자가 컨텍스트 길이, 즉 "한 번에 기억할 수 있는 최대 분량"입니다. KV 캐시는 그 기억을 실제로 담아두는 공간이고요.

컨텍스트 = 기억할 수 있는 최대치 (약속) · KV 캐시 = 실제로 쓰는 메모리 (현실)

그래서 q8_0으로 압축합니다

OLLAMA_FLASH_ATTENTION = 1 ← 이게 켜져 있어야 OLLAMA_KV_CACHE_TYPE = q8_0 ← 이게 동작합니다
✅ 얻는 것
  • 기본 f16 대비 KV 캐시가 약 절반 크기가 됩니다
  • 캐시 공간을 절약해 더 긴 컨텍스트 설정에 도움
  • 품질 영향은 모델과 작업에 따라 다릅니다
⚠️ 주의
  • 두 개를 같이 넣어야 합니다. Flash Attention이 꺼져 있으면 압축이 조용히 무시됩니다
  • 일부 오래된 모델은 지원하지 않습니다
🔴 오늘 실습에서 이게 이렇게 나타납니다 바이브코딩은 코드 전체를 계속 주고받기 때문에 메모장이 아주 빨리 찹니다. 대화가 길어지면 이런 증상이 나옵니다:

준비 · 프로젝트 전용 venv

다음 차시에는 Python 기본 내장 GUI인 tkinter로 화면을 만듭니다. 교사가 배포한 Python이 설치되어 있어야 합니다. VS Code에서 파일 → 폴더 열기로 새 error-tutor 폴더를 엽니다.

터미널 → 새 터미널 옆 드롭다운에서 Command Prompt(cmd)를 선택합니다. 터미널 위치가 error-tutor 폴더인지 확인한 뒤 한 줄씩 실행하세요.

py -m venv .venv .venv\Scripts\activate.bat python -m pip install --upgrade pip setuptools wheel python -m pip install "requests>=2.32,<3" python -c "import sys; print(sys.executable)" python -c "import tkinter, requests; print(tkinter.TkVersion)"
pip 설치 전에 setuptools·wheel 업그레이드부터 새 venv에서 바로 패키지를 설치하면 "모듈을 찾을 수 없다"는 설치 오류가 나는 PC가 있습니다. 위처럼 pip setuptools wheel을 먼저 올려두면 피할 수 있어요. 나중에 PySide6 같은 큰 GUI 패키지를 시도할 때는 특히 필수입니다.
GUI 설치가 없는 이유 tkinter는 Python에 기본 포함이라 설치할 게 없습니다. 마지막 줄에서 버전이 찍히면 준비 끝. 숫자 대신 오류가 나면 Python을 설치할 때 tcl/tk 옵션이 빠진 것이니 교사에게 알리세요.

경로 끝이 error-tutor\.venv\Scripts\python.exe인지 확인합니다. 패키지는 프로젝트의 .venv에 설치합니다. py가 없으면 교사와 Python 설치를 확인하고 python -m venv .venv를 사용합니다.

편집기와 실행 환경 맞추기VS Code에 Python 확장이 설치되어 있다면 Ctrl+Shift+P → Python: Select Interpreter → .venv의 python.exe를 선택합니다. 목록에 없으면 경로를 직접 지정합니다. Python 확장이 없어도 활성화한 cmd에서 실행할 수 있습니다. 새 터미널을 열면 다시 활성화하고, 활성화 문제는 .venv\Scripts\python.exe tutor_app.py처럼 직접 실행해 확인합니다.

이 명령은 Windows cmd용입니다. PowerShell의 Activate.ps1 실행 정책을 바꾸는 대신 cmd 터미널을 선택하세요. 패키지 다운로드는 수업 전에 완료합니다. .venv는 PC별로 만들고 다른 PC에서 복사해 재사용하지 않습니다. requirements.txt를 받았다면 설치 명령 대신 python -m pip install -r requirements.txt를 사용해도 됩니다.

{ "model": "qwen2.5-coder:3b", "message": { "role": "assistant", "content": "리스트의 범위를 벗어난 위치를 읽으려 했기 때문입니다." ← 우리가 원하는 것 }, "done": true }

roleuser(나) / assistant(AI) / system(역할 지시)

timeout 을 반드시 넉넉히 로컬 모델은 10~40초가 예사입니다. 기본값이나 짧은 값으로 두면 정상 동작인데도 계속 실패합니다. 180초 이상 권장합니다.

왜 스레드 + after 폴링인가요?화면을 그리는 메인 스레드가 HTTP 응답까지 기다리면 창이 얼어붙습니다. 그래서 요청은 작업 스레드가 하고, 결과를 변수에 저장만 합니다. 메인 스레드는 root.after(100, ...)로 0.1초마다 그 변수를 확인해 화면에 그립니다. tkinter 위젯은 메인 스레드에서만 건드린다 — 이 규칙 하나가 GUI 프로그래밍의 핵심입니다. 학생은 "분석 중에도 창을 움직이고 결과를 스크롤할 수 있는지"로 확인합니다.

닫기 안내는 단순한 수업용 정책입니다. 즉시 취소 기능은 구현하지 않습니다. 파이썬 스레드는 밖에서 강제로 멈출 수 없어서, 진행 중인 requests 호출은 끝나거나 timeout 될 때까지 달립니다. timeout도 정확한 전체 분석 제한 시간이 아니라 연결·읽기 대기 제한입니다.

같은 형식으로 요청해도 모델이 항상 규칙을 지키는 것은 아닙니다. 답변 형식과 해결책의 정확성은 따로 검증합니다.
