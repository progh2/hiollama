1LLM이 뭔가요?

Large Language Model — 커다란 언어 모델.

하는 일은 딱 하나입니다: 다음 단어 맞히기

"오늘 아침에 밥을 ___" 다음에 올 말을 맞히는 것. 이 단순한 작업을 인터넷 전체 분량의 글로 어마어마하게 훈련시켰더니, 번역도 하고 요약도 하고 코드도 짜는 물건이 나왔습니다.

그래서 LLM은 "알고 있는 것"이 아니라 "그럴듯한 것"을 내놓습니다. 이게 오늘 실습 내내 체감하게 될 핵심 성질입니다. 자신 있게 틀린 답을 말하는 이유이기도 하고요.

파라미터 — 모델의 "크기"

모델 이름에 붙는 4B, 7B, 70B의 B는 Billion(10억), 즉 파라미터 개수입니다. 뇌세포 개수 같은 거라고 생각하면 얼추 맞습니다.

크기비유어디서 도나
1B~4B간단한 일은 척척, 복잡한 건 헤맴노트북, 게이밍 PC ← 오늘 우리
7B~14B웬만한 건 해냄좋은 그래픽카드 (12~24GB)
30B~70B꽤 똑똑함전문가용 장비
200B+ChatGPT, Claude 급데이터센터 — 개인은 불가능
미리 알아두기 오늘 쓸 모델은 가장 작은 축입니다. ChatGPT를 기대하면 실망합니다. 대신 내 컴퓨터에서, 공짜로, 인터넷 없이 돕니다. 그 대가를 오늘 직접 확인해 봅시다.

2왜 굳이 내 PC에서?

ChatGPT 놔두고 왜 이 고생을 하는가.

클라우드 (ChatGPT, Claude)로컬 (오늘 우리)
성능압도적제한적
비용쓸수록 과금전기값만
인터넷반드시 필요없어도 됨
내 데이터서버로 전송됨PC 밖으로 안 나감
사용 제한횟수·속도 제한없음
서비스 종료회사 사정에 좌우내 파일이라 영향 없음

현실에서 로컬이 답인 경우

  • 회사 소스코드 — 외부 AI에 붙여넣는 순간 유출입니다. 실제로 금지된 회사가 많습니다
  • 병원 기록, 개인정보, 미공개 연구 — 법적으로 못 내보내는 데이터
  • 인터넷이 없는 환경 — 폐쇄망, 공장, 군, 비행기
  • 대량 반복 처리 — 10만 건 분류를 API로 돌리면 요금이 폭발합니다
오늘의 진짜 학습 목표 "로컬이 좋다"가 아니라 "어떤 일에 로컬을 쓰고 어떤 일에 클라우드를 쓸지 판단할 줄 아는 것"입니다. 양쪽을 다 써본 사람만 판단할 수 있습니다.

3모델에도 종류가 있습니다

모델을 고를 때 봐야 하는 세 가지 축.

① 용도 — 범용이냐 코딩 특화냐

종류용도
범용 (Instruct/Chat)일상 대화, 글쓰기, 요약
코더 (Coder)코드 생성·설명·수정 ← 오늘 이걸 씁니다
임베딩 (Embedding)문서 검색용. 대화는 못 함
비전 (Vision)이미지를 보고 설명

같은 4B라도 코더 모델이 코딩을 훨씬 잘합니다. 크기만 보고 고르면 안 되는 이유입니다.

② 양자화 — 모델을 압축하는 기술

원본 모델은 숫자 하나를 16비트로 저장합니다. 이걸 4비트로 줄이면 용량이 1/4이 되죠. 이게 양자화(Quantization)이고, 이름 뒤의 Q4, Q8이 그 표시입니다.

표기용량품질
F16 (원본)4B 모델 = 약 8GB100%
Q44B 모델 = 약 2.5GB거의 그대로 ← 표준
Q84B 모델 = 약 4.5GB사실상 원본
기억할 규칙 같은 용량이라면 "작은 모델을 고품질로" 보다 "큰 모델을 Q4로"가 거의 항상 낫습니다.

③ VRAM — 그래픽카드 메모리가 천장입니다

모델은 그래픽카드 메모리(VRAM)에 통째로 올라가야 빠릅니다. 안 들어가면 일부가 일반 메모리로 밀려나면서 몇 배로 느려집니다.

내 그래픽카드돌릴 수 있는 모델
RTX 2060 (6GB) ← 실습실 PC4B Q4 (약 2.5GB) 안정 / 7B는 아슬아슬
RTX 3080 (12GB)8B~14B
RTX 3090 / A5000 (24GB)14B~32B

참고로 우리 실습실 2060의 메모리 속도는 초당 336GB입니다. 이 숫자가 글자가 찍혀 나오는 속도를 결정합니다.

오늘 쓸 모델과 후보들

모델용량성격
qwen2.5-coder:3b1.9GB코딩 전용. 작지만 코드는 잘 씀 ← 오늘 이것
qwen2.5-coder:7b4.7GB더 잘하지만 6GB엔 아슬아슬
gemma3:4b3.3GB범용. 대화·한국어가 더 자연스러움
qwen2.5-coder:1.5b1.0GB저사양 PC용 예비
🔴 이름에 속지 마세요 — 대표적인 함정 gemma4:e2b는 이름이 "2B"라서 작아 보이지만 실제 용량은 7.2GB입니다. "E"는 effective(유효) 파라미터라는 뜻이라, 실제로 저장되는 크기는 훨씬 큽니다. 모델을 고를 때는 이름이 아니라 GB 용량을 보세요.
같은 크기면 "전용 모델"이 이깁니다 qwen2.5-coder:3b는 3B밖에 안 되지만 코딩만 훈련받아서 비슷한 크기의 범용 모델보다 코드를 훨씬 잘 씁니다. 크기가 전부가 아닙니다.

4Ollama가 하는 일

모델을 내 PC에서 굴리기 쉽게 만들어주는 프로그램.

원래 로컬 LLM은 설정이 지옥이었습니다. Ollama는 이걸 명령어 한 줄로 만들었습니다.

  • 모델 관리 — 내려받고, 목록 보고, 지우고
  • 실행 — 그래픽카드 설정을 알아서 해줌
  • API 서버 — 실행하면 localhost:11434에 서버가 자동으로 뜹니다

세 번째가 핵심입니다. 이 포트 덕분에 VS Code가 내 PC 안의 AI에 접속할 수 있습니다. 오늘 우리가 할 일이 정확히 이겁니다.

[ VS Code ] ──▶ localhost:11434 ──▶ [ Ollama ] ──▶ [ RTX 2060 ] 내가 쓰는 곳 내 PC 안 프로그램 실제 연산

설치 전에 이 PC가 준비됐는지 한 번에 확인합니다.

아래 두 파일을 같은 폴더에 내려받고 run-check.bat을 더블클릭하세요.

무엇을 확인하나

항목통과 기준

초록색 [OK]만 있으면 통과 빨간 [경고]가 뜨면 그 줄을 조교에게 보여주세요. 특히 드라이버 551.61 미만은 수업 전에 반드시 해결해야 합니다.

powershell -NoProfile -ExecutionPolicy Bypass -File .\check-env.ps1

실습 ①설치하기 · 15분

파일은 이미 나눠드렸습니다. 인터넷에서 받지 마세요 — 18명이 동시에 받으면 수업이 끝납니다.

STEP 1

Ollama 설치

배포된 OllamaSetup.exe를 실행하고 기본값으로 진행하세요.

관리자 권한 필요 없습니다 내 계정 안에 설치되므로 실습실 PC의 권한 제한과 무관합니다.

설치가 끝나면 작업표시줄 오른쪽에 Ollama 아이콘이 생깁니다.

STEP 2

Ollama 종료

작업표시줄 아이콘을 우클릭 → Quit. 모델 파일을 넣는 동안은 꺼져 있어야 합니다.

STEP 3

모델 파일 복사 — 가장 중요한 단계

배포된 blobs와 manifests 두 폴더를 아래 경로에 통째로 붙여넣습니다.

%USERPROFILE%\.ollama\models

탐색기 주소창에 그대로 붙여넣으면 해당 폴더로 이동합니다. 폴더가 없으면 만드세요.

🔴 가장 많이 하는 실수 manifests 폴더를 빠뜨리는 것. blobs만 복사하면 파일은 다 있는데 모델 목록에 아무것도 안 뜹니다. 원인을 찾기 어려우니 두 폴더 다 복사했는지 지금 확인하세요.
STEP 4

환경변수 2개 설정

메모리를 아껴서 더 긴 대화를 가능하게 하는 설정입니다.

Win 키 → "환경 변수" 검색 → 계정의 환경 변수 편집 → 새로 만들기로 두 개 추가:

OLLAMA_FLASH_ATTENTION = 1 OLLAMA_KV_CACHE_TYPE = q8_0

추가한 뒤 Ollama를 다시 실행하세요. (시작 메뉴에서 Ollama 실행)

STEP 5

확인

Win+R → cmd → 엔터. 검은 창에 입력:

ollama list

모델 이름이 한 줄 뜨면 성공입니다. 아무것도 안 뜨면 STEP 3의 manifests를 확인하세요.

그래픽카드를 제대로 쓰는지도 확인해 둡시다:

nvidia-smi

카드 이름과 메모리(6GB 내외), 드라이버 버전이 나옵니다. 드라이버가 551.61 미만이면 그래픽카드를 못 쓰고 매우 느려집니다 — 조교에게 알려주세요.

실습 ②첫 대화 · 10분

VS Code로 가기 전에, 검은 창에서 직접 말을 걸어봅니다.

아래 모델명 자리에 ollama list에서 본 이름을 넣으세요.

ollama run 모델명

잠깐 로딩된 뒤 프롬프트가 뜹니다. 아무거나 물어보세요.

해볼 것자바스크립트에서 배열의 중복을 제거하는 가장 짧은 방법은?

관찰해 볼 것 세 가지

  1. 속도 — 글자가 실시간으로 찍혀 나옵니다. 이게 내 2060이 계산하고 있는 속도입니다
  2. 인터넷을 꺼도 됩니다 — 랜선을 뽑고 다시 물어보세요. 똑같이 답합니다
  3. 한국어 vs 영어 — 같은 질문을 영어로도 던져보세요. 영어 답변 품질이 대체로 더 좋습니다. 작은 모델일수록 차이가 큽니다

나가려면:

/bye
지금 무슨 일이 일어났나 방금 내 PC의 그래픽카드가 AI를 돌렸습니다. 서버도, 계정도, 결제도, 인터넷도 없이요. 이게 오늘 수업의 전부이자 핵심입니다.

실습 ③VS Code에 연결 · 15분

이제 개발 도구 안에서 AI를 씁니다.

STEP 1

Ollama 확장 설치

VS Code 왼쪽의 확장(Extensions) 아이콘 → Ollama 검색 → 게시자가 Ollama인 공식 확장을 설치.

검색하면 나오는 옛날 글에 주의 "Manage Models에서 Ollama 선택"이라고 안내하는 자료가 많은데, 그 방식은 더 이상 지원되지 않습니다. 반드시 공식 Ollama 확장을 설치하세요. VS Code는 1.127 이상이어야 합니다.
STEP 2

채팅 열고 모델 선택

채팅 창을 열고, 입력칸 아래쪽 모델 선택기를 클릭 → Ollama 항목에서 우리 모델을 고릅니다.

GitHub 로그인도, Copilot 구독도 필요 없습니다 로컬 모델은 계정 없이, 인터넷 없이 동작합니다. 결제 정보도 필요 없습니다.
STEP 3

연결 확인

채팅에 아무거나 쳐보세요. 답이 오면 연결 성공입니다.

모델이 안 보이면 → 작업표시줄에 Ollama가 켜져 있는지, ollama list에 모델이 뜨는지 확인.

실습 ④바이브코딩 맛보기 · 30분

코드를 직접 쓰지 않고, 말로 시켜서 프로그램을 만듭니다.

바이브코딩의 루프

① 말로 요청 → ② 코드 받기 → ③ 붙여넣고 실행 → ④ 보고 다시 요청 ↑______________|

핵심은 한 번에 완벽한 걸 기대하지 않는 것입니다. 빨리 만들고, 보고, 고치라고 시킵니다. 이 반복이 바이브코딩입니다.

왜 "HTML 파일 하나"인가

  • 설치할 게 없습니다 — 더블클릭하면 브라우저에서 바로 실행
  • 결과가 눈에 보입니다 — 됐는지 안 됐는지 즉시 판단
  • 파일이 하나라 작은 모델도 감당할 수 있는 크기

▶ 따라하기 — 강사와 함께

프롬프트 1 · 만들기가위바위보 게임을 만들어줘. 조건: - HTML, CSS, JavaScript를 파일 하나에 모두 넣어줘 - 외부 라이브러리나 CDN은 절대 사용하지 마 - 버튼 3개(가위/바위/보)를 누르면 컴퓨터가 랜덤으로 내고 승패를 표시 - 전체 코드를 한 번에, 생략 없이 보여줘
🔴 "CDN 사용 금지"를 반드시 넣으세요 AI는 습관적으로 React나 Tailwind 같은 외부 라이브러리 주소를 코드에 넣습니다. 그러면 인터넷이 없거나 느릴 때 화면이 하얗게 비어서 뜨고, 원인을 찾기 매우 어렵습니다. 오늘 가장 많이 터질 사고입니다.

받은 코드 실행하기

  1. VS Code에서 Ctrl+N → 새 파일
  2. 코드 블록 오른쪽 위 복사 버튼 → 붙여넣기
  3. Ctrl+S → 바탕화면에 game.html로 저장
  4. 바탕화면에서 더블클릭 → 브라우저에서 실행
프롬프트 2 · 고치기좋아. 이제 점수판을 추가해줘. 이긴 횟수와 진 횟수를 화면에 표시하고, 초기화 버튼도 넣어줘. 수정된 전체 코드를 다시 보여줘.
프롬프트 3 · 꾸미기디자인을 개선해줘. 버튼을 크고 둥글게, 배경에 부드러운 그라데이션, 결과가 나올 때 살짝 나타나는 애니메이션을 넣어줘. 전체 코드를 다시 보여줘.
"전체 코드를 다시 보여줘"를 매번 넣으세요 안 넣으면 AI가 "이 부분만 이렇게 바꾸세요" 하고 조각만 줍니다. 작은 모델을 쓸 땐 파일 전체를 통째로 받아 덮어쓰는 게 훨씬 빠르고 안 헷갈립니다.

6이럴 땐 이렇게

오늘 실제로 터질 문제들.

증상해결
브라우저 화면이 하얗게 빈다 CDN 링크가 들어간 경우입니다. "외부 라이브러리 없이 다시 만들어줘"라고 요청하세요. 가장 흔합니다
코드가 중간에 끊긴다 이어서 계속 보여줘라고 요청. 또는 기능을 줄여서 다시 요청
ollama list에 아무것도 없다 manifests 폴더를 복사했는지 확인 (설치 STEP 3)
VS Code에 모델이 안 보인다 작업표시줄에 Ollama가 켜져 있는지 확인 → VS Code 재시작
너무 느리다 첫 응답은 모델 로딩이라 느립니다. 계속 느리면 아래 ollama ps 확인
답변이 엉뚱하다 영어로 다시 시도 / 요청을 더 잘게 쪼개기 / 조건을 구체적으로
같은 실수를 반복한다 대화가 길어져서 앞을 잊은 겁니다. 새 대화를 시작하고 처음부터 다시 요청하세요

속도가 안 나올 때 확인

ollama ps

100% GPU로 나와야 정상입니다. CPU 비율이 잡히면 모델이 그래픽카드에 다 안 들어간 겁니다 → 조교에게 알려주세요 (더 작은 모델로 교체).

집에서 이어가려면

오늘 설치한 건 전부 내 것입니다. 수업이 끝나도 그대로 남아 있고, 집 PC에도 똑같이 설치할 수 있습니다. 이게 서버로 실습하지 않은 이유입니다.

  • 모델 받기 — 인터넷이 되는 곳에서 ollama pull 모델명
  • 모델 찾기 — ollama.com/search 에서 크기·용도별로 탐색
  • 내 PC가 더 좋은 그래픽카드라면 더 큰 모델에 도전 (VRAM의 60~70% 이내)
  • 공식 문서 — docs.ollama.com

더 나아가고 싶다면

  • Modelfile — 나만의 성격을 가진 AI 만들기
  • REST API — localhost:11434에 직접 요청을 보내 내 프로그램에 AI 붙이기
  • RAG — 내 문서를 읽고 답하는 AI 만들기
