01

LLM이 뭔가요

라마

나 같은 애들은 사실 '다음 단어 맞히기' 선수야.

Large Language Model — 커다란 언어 모델.

하는 일은 딱 하나입니다: 다음 단어 맞히기

"오늘 아침에 밥을 ___" 다음에 올 말을 맞히는 것. 이 단순한 작업을 인터넷 전체 분량의 글로 어마어마하게 훈련시켰더니, 번역도 하고 요약도 하고 코드도 짜는 물건이 나왔습니다.

그래서 LLM은 "알고 있는 것"이 아니라 "그럴듯한 것"을 내놓습니다. 이게 오늘 실습 내내 체감하게 될 핵심 성질입니다. 자신 있게 틀린 답을 말하는 이유이기도 하고요.

파라미터 — 모델의 "크기"

모델 이름에 붙는 4B, 7B, 70B의 B는 Billion(10억), 즉 파라미터 개수입니다. 뇌세포 개수 같은 거라고 생각하면 얼추 맞습니다.

크기비유어디서 도나
1B~4B간단한 일은 척척, 복잡한 건 헤맴노트북, 게이밍 PC ← 오늘 우리
7B~14B웬만한 건 해냄좋은 그래픽카드 (12~24GB)
30B~70B꽤 똑똑함전문가용 장비
200B+ChatGPT, Claude 급데이터센터 — 개인은 불가능
미리 알아두기 오늘 쓸 모델은 가장 작은 축입니다. ChatGPT를 기대하면 실망합니다. 대신 내 컴퓨터에서, 공짜로, 인터넷 없이 돕니다. 그 대가를 오늘 직접 확인해 봅시다.
02

왜 내 PC에서?

라마

인터넷이 없어도, 내가 네 컴퓨터 안에 있으면 되잖아?

ChatGPT 놔두고 왜 이 고생을 하는가.

클라우드 (ChatGPT, Claude)로컬 (오늘 우리)
성능압도적제한적
비용쓸수록 과금전기값만
인터넷반드시 필요없어도 됨
내 데이터서버로 전송됨PC 밖으로 안 나감
사용 제한횟수·속도 제한없음
서비스 종료회사 사정에 좌우내 파일이라 영향 없음

현실에서 로컬이 답인 경우

  • 회사 소스코드 — 외부 AI에 붙여넣는 순간 유출입니다. 실제로 금지된 회사가 많습니다
  • 병원 기록, 개인정보, 미공개 연구 — 법적으로 못 내보내는 데이터
  • 인터넷이 없는 환경 — 폐쇄망, 공장, 군, 비행기
  • 대량 반복 처리 — 10만 건 분류를 API로 돌리면 요금이 폭발합니다
오늘의 진짜 학습 목표 "로컬이 좋다"가 아니라 "어떤 일에 로컬을 쓰고 어떤 일에 클라우드를 쓸지 판단할 줄 아는 것"입니다. 양쪽을 다 써본 사람만 판단할 수 있습니다.
03

모델 고르는 법

라마

덩치보다 뭘 배웠느냐가 중요해. 나는 코딩만 팠거든.

모델을 고를 때 봐야 하는 세 가지 축.

① 용도 — 범용이냐 코딩 특화냐

종류용도
범용 (Instruct/Chat)일상 대화, 글쓰기, 요약
코더 (Coder)코드 생성·설명·수정 ← 오늘 이걸 씁니다
임베딩 (Embedding)문서 검색용. 대화는 못 함
비전 (Vision)이미지를 보고 설명

같은 4B라도 코더 모델이 코딩을 훨씬 잘합니다. 크기만 보고 고르면 안 되는 이유입니다.

② 양자화 — 모델을 압축하는 기술

원본 모델은 숫자 하나를 16비트로 저장합니다. 이걸 4비트로 줄이면 용량이 1/4이 되죠. 이게 양자화(Quantization)이고, 이름 뒤의 Q4, Q8이 그 표시입니다.

표기4B 모델 기준품질
F16 (원본)약 8GB100%
Q8약 4.5GB사실상 원본
Q4약 2.5GB거의 그대로 ← 표준
Q3 이하더 작음눈에 띄게 나빠짐 ⚠️
✅ 좋은 점
  • 안 돌아가던 모델이 돌아갑니다 — 8GB짜리가 2.5GB가 되니까
  • 더 빨라집니다 — 읽어야 할 데이터가 적어지니 글자가 빨리 나옵니다
  • 같은 그래픽카드에 한 등급 큰 모델을 넣을 수 있습니다
⚠️ 나쁜 점
  • 품질이 조금 깎입니다 — Q4까지는 대부분 티가 안 납니다
  • 고르게 깎이지 않습니다 — 긴 코드, 복잡한 추론, 계산에서 먼저 티가 납니다
  • Q3 아래로 가면 급격히 무너집니다 — 용량은 조금 줄고 품질은 많이 잃습니다
외워둘 규칙 2가지
  1. 같은 용량이라면 "작은 모델을 Q8로" 보다 "큰 모델을 Q4로"가 거의 항상 낫습니다
  2. Q4 아래로는 내려가지 마세요. 얻는 것보다 잃는 게 큽니다

③ 멀티모달 — 글만 읽나, 그림도 보나

모델에 따라 이미지나 소리까지 이해하는 것들이 있습니다. gemma3:4b는 그림을 보고, qwen2.5-coder:3b는 글만 읽습니다.

✅ 멀티모달의 매력
  • 디자인 시안 사진을 주고 "이렇게 만들어줘" — 바이브코딩과 직결됩니다
  • 에러 화면을 스크린샷으로 보여주며 물어보기
  • 표·차트·손글씨 메모를 읽어서 정리
⚠️ 공짜가 아닙니다
  • 같은 크기면 글 실력이 떨어집니다 — 한정된 파라미터를 그림 이해에도 나눠 쓰니까요
  • 이미지 처리 부품이 VRAM을 추가로 먹습니다
  • 사진 한 장이 글자 수천 개 분량을 차지해서 대화가 금방 꽉 찹니다
비교qwen2.5-coder:3bgemma3:4b
이미지 이해❌✅
코드 작성강함보통
한국어 대화보통자연스러움
용량1.9GB3.3GB
그래서 오늘은 글만 읽는 모델을 씁니다 우리 목적은 코드 만들기입니다. 6GB라는 한정된 공간에 그림 보는 능력에 자리를 내주는 것보다, 코딩에 전부 쓰는 게 낫습니다. "기능이 많은 쪽이 좋다"가 아니라 "내 목적에 맞는 쪽이 좋다"는 게 모델 선택의 핵심입니다.
04

내 PC에 맞추기

라마

메모장이 꽉 차면 나도 앞 얘기를 까먹어.

④ KV 캐시 — 대화를 기억하는 공간

설치할 때 OLLAMA_KV_CACHE_TYPE = q8_0을 넣었죠. 그게 뭔지 알아봅시다.

왜 필요한가

LLM은 대답할 때마다 대화 전체를 처음부터 다시 읽습니다. 10번째 질문에 답하려면 1~9번 대화를 전부 다시 훑어야 하죠. 그대로 두면 대화가 길어질수록 점점 느려집니다.

그래서 앞 내용을 계산해둔 결과를 메모해 둡니다. 이 메모장이 KV 캐시예요. 책을 읽다가 앞 장을 다시 펼치지 않으려고 요점을 적어두는 것과 같습니다. 덕분에 대화가 길어져도 새 답변만 계산하면 됩니다.

문제는 — 이 메모장도 VRAM을 먹습니다

그래픽카드 6GB ├─ 모델 본체 1.9GB ← 고정 └─ KV 캐시(메모장) ?GB ← 대화가 길어질수록 계속 커짐

모델을 넣었다고 끝이 아닙니다. 대화를 주고받을수록 메모장이 불어나고, 남은 공간을 다 쓰면 느려지거나 터집니다. 작은 모델일수록 본체보다 메모장이 더 커지는 일도 흔합니다.

컨텍스트와의 관계

모델 설명에 나오는 32K, 128K 같은 숫자가 컨텍스트 길이, 즉 "한 번에 기억할 수 있는 최대 분량"입니다. KV 캐시는 그 기억을 실제로 담아두는 공간이고요.

컨텍스트 = 기억할 수 있는 최대치 (약속) · KV 캐시 = 실제로 쓰는 메모리 (현실)

그래서 q8_0으로 압축합니다

OLLAMA_FLASH_ATTENTION = 1 ← 이게 켜져 있어야 OLLAMA_KV_CACHE_TYPE = q8_0 ← 이게 동작합니다
✅ 얻는 것
  • 메모장 크기가 절반이 됩니다
  • 같은 VRAM으로 약 2배 긴 대화가 가능
  • 품질 영향은 거의 없습니다
⚠️ 주의
  • 두 개를 같이 넣어야 합니다. Flash Attention이 꺼져 있으면 압축이 조용히 무시됩니다
  • 일부 오래된 모델은 지원하지 않습니다
🔴 오늘 실습에서 이게 이렇게 나타납니다 바이브코딩은 코드 전체를 계속 주고받기 때문에 메모장이 아주 빨리 찹니다. 대화가 길어지면 이런 증상이 나옵니다:
  • 점점 느려진다
  • 앞에서 한 요청을 잊어버린다
  • 같은 실수를 계속 반복한다
→ 이럴 땐 새 대화를 시작하세요. 메모장을 비우는 겁니다. 그동안 만든 코드를 붙여넣고 다시 시작하면 훨씬 잘 됩니다.

⑤ VRAM — 그래픽카드 메모리가 천장입니다

모델은 그래픽카드 메모리(VRAM)에 통째로 올라가야 빠릅니다. 안 들어가면 일부가 일반 메모리로 밀려나면서 몇 배로 느려집니다.

내 그래픽카드돌릴 수 있는 모델
RTX 2060 (6GB) ← 실습실 PC4B Q4 (약 2.5GB) 안정 / 7B는 아슬아슬
RTX 3080 (12GB)8B~14B
RTX 3090 / A5000 (24GB)14B~32B

참고로 우리 실습실 2060의 메모리 속도는 초당 336GB입니다. 이 숫자가 글자가 찍혀 나오는 속도를 결정합니다.

오늘 쓸 모델과 후보들

모델용량성격
qwen2.5-coder:3b1.9GB코딩 전용. 작지만 코드는 잘 씀 ← 오늘 이것
qwen2.5-coder:7b4.7GB더 잘하지만 6GB엔 아슬아슬
gemma3:4b3.3GB범용. 대화·한국어가 더 자연스러움
qwen2.5-coder:1.5b1.0GB저사양 PC용 예비
🔴 이름에 속지 마세요 — 대표적인 함정 gemma4:e2b는 이름이 "2B"라서 작아 보이지만 실제 용량은 7.2GB입니다. "E"는 effective(유효) 파라미터라는 뜻이라, 실제로 저장되는 크기는 훨씬 큽니다. 모델을 고를 때는 이름이 아니라 GB 용량을 보세요.
같은 크기면 "전용 모델"이 이깁니다 qwen2.5-coder:3b는 3B밖에 안 되지만 코딩만 훈련받아서 비슷한 크기의 범용 모델보다 코드를 훨씬 잘 씁니다. 크기가 전부가 아닙니다.
05

Ollama란

라마

11434 — 이게 내 방 번호야. 기억해 둬.

모델을 내 PC에서 굴리기 쉽게 만들어주는 프로그램.

원래 로컬 LLM은 설정이 지옥이었습니다. Ollama는 이걸 명령어 한 줄로 만들었습니다.

  • 모델 관리 — 내려받고, 목록 보고, 지우고
  • 실행 — 그래픽카드 설정을 알아서 해줌
  • API 서버 — 실행하면 localhost:11434에 서버가 자동으로 뜹니다

세 번째가 핵심입니다. 이 포트 덕분에 VS Code가 내 PC 안의 AI에 접속할 수 있습니다. 오늘 우리가 할 일이 정확히 이겁니다.

[ VS Code ] ──▶ localhost:11434 ──▶ [ Ollama ] ──▶ [ RTX 2060 ] 내가 쓰는 곳 내 PC 안 프로그램 실제 연산

창이 바로 닫히면 Win+R → cmd → 엔터로 검은 창을 먼저 연 뒤, 배치 파일을 그 창에 끌어다 놓고 엔터를 치세요. 오류 메시지를 볼 수 있습니다.

설치하기

라마

manifests 폴더 빼먹으면 나 안 보여. 진짜야!

Ollama를 깔고, 모델을 가져오고, 잘 되는지 확인합니다.

STEP 1

Ollama 설치

배포된 OllamaSetup.exe를 실행하고 기본값으로 진행하세요.

파일이 없거나 집에서 설치한다면 → ollama.com/download/windows (바로 받기: OllamaSetup.exe)

관리자 권한 필요 없습니다 내 계정 안에 설치되므로 실습실 PC의 권한 제한과 무관합니다.

설치가 끝나면 작업표시줄 오른쪽에 Ollama 아이콘이 생깁니다.

STEP 2

모델 가져오기 — 가장 중요한 단계

두 가지 방법이 있습니다. 조교 안내에 따라 하나만 하세요.

■ 방법 A · 배포 파일 복사 (권장 — 훨씬 빠릅니다)

  1. 작업표시줄 Ollama 아이콘 우클릭 → Quit (복사하는 동안 꺼져 있어야 합니다)
  2. 배포된 blobs, manifests 두 폴더를 아래 경로에 통째로 붙여넣기
    %USERPROFILE%\.ollama\models
    탐색기 주소창에 붙여넣으면 해당 폴더로 이동합니다. 없으면 만드세요.
  3. 시작 메뉴에서 Ollama 다시 실행
🔴 가장 많이 하는 실수 manifests 폴더를 빠뜨리는 것. blobs만 복사하면 파일은 다 있는데 모델 목록에 아무것도 안 뜹니다. 원인을 찾기 어려우니 두 폴더 다 복사했는지 지금 확인하세요.

■ 방법 B · 직접 다운로드

인터넷에서 바로 받습니다. Ollama가 켜져 있어야 합니다.

Win+R → cmd → 엔터. 검은 창에 입력:

ollama pull qwen2.5-coder:3b

진행률이 표시되고, 1.9GB라 회선 상태에 따라 몇 분 걸립니다. success가 뜨면 완료입니다.

18명이 동시에 받으면 느려집니다 교육장 회선을 다 같이 나눠 쓰게 됩니다. 조교가 방법 A를 안내했다면 그쪽을 쓰세요. 직접 받아야 한다면, 다 받을 때까지 기다리지 말고 먼저 끝난 사람부터 다음 단계로 넘어가면 됩니다.
저사양 PC용 대체 모델 점검 결과 VRAM이 부족하다고 나왔다면 더 작은 모델을 받으세요.
ollama pull qwen2.5-coder:1.5b
STEP 3

환경변수 2개 설정

대화 기억 공간(KV 캐시)을 절반으로 압축해서, 같은 그래픽카드로 더 긴 대화를 가능하게 하는 설정입니다. (자세한 설명은 04 내 PC에 맞추기)

Win 키 → "환경 변수" 검색 → 계정의 환경 변수 편집 → 새로 만들기로 두 개 추가:

OLLAMA_FLASH_ATTENTION = 1 OLLAMA_KV_CACHE_TYPE = q8_0

추가한 뒤 Ollama를 다시 실행하세요. (시작 메뉴에서 Ollama 실행)

STEP 4

확인

Win+R → cmd → 엔터. 검은 창에 입력:

ollama list

qwen2.5-coder:3b가 뜨면 성공입니다. 아무것도 안 뜨면 STEP 2의 manifests를 확인하세요.

그래픽카드를 제대로 쓰는지도 확인해 둡시다:

nvidia-smi

카드 이름과 메모리(6GB 내외), 드라이버 버전이 나옵니다.

⚠️ 드라이버 551.61 이상이어야 합니다 미만이면 그래픽카드를 못 쓰고 CPU로 동작해 매우 느려집니다.

확인하는 방법 (셋 중 아무거나)

  • nvidia-smi — 오른쪽 위 Driver Version
  • 바탕화면 우클릭 → NVIDIA 제어판 → 좌측 하단 시스템 정보
  • Win+R → dxdiag → 디스플레이 탭

낮으면 업데이트

nvidia.com/ko-kr/drivers 에서 카드 모델을 선택해 받거나, NVIDIA 앱으로 자동 업데이트. 수업 중에 하기엔 오래 걸리니 조교에게 먼저 알려주세요.

라마

한 번에 완벽하게? 그런 건 없어. 세 번 고쳐.

코드를 직접 쓰지 않고, 말로 시켜서 프로그램을 만듭니다.

바이브코딩의 루프

① 말로 요청 → ② 코드 받기 → ③ 붙여넣고 실행 → ④ 보고 다시 요청 ↑______________|

핵심은 한 번에 완벽한 걸 기대하지 않는 것입니다. 빨리 만들고, 보고, 고치라고 시킵니다. 이 반복이 바이브코딩입니다.

왜 "HTML 파일 하나"인가

  • 설치할 게 없습니다 — 더블클릭하면 브라우저에서 바로 실행
  • 결과가 눈에 보입니다 — 됐는지 안 됐는지 즉시 판단
  • 파일이 하나라 작은 모델도 감당할 수 있는 크기

▶ 따라하기 — 강사와 함께

프롬프트 1 · 만들기가위바위보 게임을 만들어줘. 조건: - HTML, CSS, JavaScript를 파일 하나에 모두 넣어줘 - 외부 라이브러리나 CDN은 절대 사용하지 마 - 버튼 3개(가위/바위/보)를 누르면 컴퓨터가 랜덤으로 내고 승패를 표시 - 전체 코드를 한 번에, 생략 없이 보여줘
🔴 "CDN 사용 금지"를 반드시 넣으세요 AI는 습관적으로 React나 Tailwind 같은 외부 라이브러리 주소를 코드에 넣습니다. 그러면 인터넷이 없거나 느릴 때 화면이 하얗게 비어서 뜨고, 원인을 찾기 매우 어렵습니다. 오늘 가장 많이 터질 사고입니다.

받은 코드 실행하기

  1. VS Code에서 Ctrl+N → 새 파일
  2. 코드 블록 오른쪽 위 복사 버튼 → 붙여넣기
  3. Ctrl+S → 바탕화면에 game.html로 저장
  4. 바탕화면에서 더블클릭 → 브라우저에서 실행
프롬프트 2 · 고치기좋아. 이제 점수판을 추가해줘. 이긴 횟수와 진 횟수를 화면에 표시하고, 초기화 버튼도 넣어줘. 수정된 전체 코드를 다시 보여줘.
프롬프트 3 · 꾸미기디자인을 개선해줘. 버튼을 크고 둥글게, 배경에 부드러운 그라데이션, 결과가 나올 때 살짝 나타나는 애니메이션을 넣어줘. 전체 코드를 다시 보여줘.
"전체 코드를 다시 보여줘"를 매번 넣으세요 안 넣으면 AI가 "이 부분만 이렇게 바꾸세요" 하고 조각만 줍니다. 작은 모델을 쓸 땐 파일 전체를 통째로 받아 덮어쓰는 게 훨씬 빠르고 안 헷갈립니다.

집에서 이어가려면

오늘 설치한 건 전부 내 것입니다. 수업이 끝나도 그대로 남아 있고, 집 PC에도 똑같이 설치할 수 있습니다. 이게 서버로 실습하지 않은 이유입니다.

  • 모델 받기 — ollama pull <모델명>
  • 모델 찾기 — ollama.com/search 에서 크기·용도별로 탐색
  • 내 PC가 더 좋은 그래픽카드라면 더 큰 모델에 도전 (VRAM의 60~70% 이내)
  • 공식 문서 — docs.ollama.com

집 PC 사양별로 받아볼 모델

ollama pull qwen2.5-coder:3b # 1.9GB - 6GB VRAM (오늘 쓴 것) ollama pull qwen2.5-coder:7b # 4.7GB - 8GB VRAM 이상 ollama pull qwen2.5-coder:14b # 9.0GB - 12GB VRAM 이상 ollama pull gemma3:4b # 3.3GB - 범용 대화용

기준: 모델 용량이 내 VRAM의 60~70% 이내여야 여유 있게 돕니다.
